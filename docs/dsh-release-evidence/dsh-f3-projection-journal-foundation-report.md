# DSH F3 Projection Journal Foundation Report

Result: **LOCAL-PARTIAL — Desktop Main serializes the live owner-scoped ACP follow stream through a finite translator, atomically stores only display-safe records with the matching durable binding sequence, and uses a durable no-replay ledger for prompt outcomes. This is not yet a product event stream or DSH availability claim.**

## Delivered locally

- Drizzle-generated migration `0101_abnormal_solo` adds `dsh_projection_events`. Its composite primary key is `(cindy_session_id, sequence)` and it references the existing DSH binding. The migration has no runtime, credential, endpoint, profile, Home-path or raw ACP field.
- [`dshProjectionJournal.ts`](../../apps/desktop/src/main/localDb/dshProjectionJournal.ts) accepts only the finite F4 DSH `AgentEvent` output types. It requires `source: 'dsh'`, exact `agentMeta.dsh.projectionSequence`, canonical JSON, a bounded UTF-8 payload and a SHA-256 digest.
- The named worker transaction `dsh.commitProjection` revalidates the persisted shape and digest, inserts its journal row, and compare-and-set advances `dsh_session_bindings.last_projected_sequence` in the same SQLite transaction. Known unsupported updates are persisted as a finite `ignored` record so they advance the observed sequence without inventing product activity.
- A duplicate is accepted only when its stored digest is identical. A gap changes the binding to `needs_reconcile` without writing an event. A malformed update takes the separate `dsh.rejectProjection` transaction: it marks reconciliation required without storing raw input or advancing the cursor. A conflicting journal row or a failed CAS rolls back the event and cursor together.
- [`dsh-follow-projection.ts`](../../apps/desktop/src/main/maker-host/dsh-follow-projection.ts) joins the finite translator and journal. [`DshControlPlane`](../../apps/desktop/src/main/maker-host/dsh-control-plane.ts) queues that work per owned Cindy session, and exposes `followCommitted` to adapters only after a translated record commits. That port explicitly constructs an owner tuple, sequence and translated events; it does not spread or carry the native `update` payload. Commit conflict, invalid update or persistence failure clears pending permission correlation, closes the carrier and requires reconciliation.
- Drizzle-generated migration `0102_conscious_iron_fist` adds `dsh_prompt_receipts`. It stores only the Cindy-generated receipt id, owning Cindy session id, finite `pending` / `acknowledged` / `uncertain` state, bounded stop reason and timestamps. It has no prompt text or digest, runtime error, endpoint, credential, profile or Home-path field.
- When the receipt store is configured for a durable bridge, `DshControlPlane` writes `pending` before `session/prompt` can reach ACP and only changes it to `acknowledged` after the native reply. Timeout, carrier loss, native failure or ledger acknowledgement failure becomes `uncertain`, closes the carrier and blocks every later prompt for that Cindy session. Recovery/history confirmation is deliberately still a future gate; the ledger never replays a prompt itself.
- A freshly initialized Main bridge may rehydrate only bindings present in its own durable scope and a fresh public `session/list` response. Before it creates even an inactive resumable binding, it reads the prompt ledger: a `pending` or `uncertain` receipt moves that binding to `needs_reconcile`, and a ledger-read failure closes the carrier. This is a no-replay restart guard, not history replay or cross-process product recovery.
- `packages/maker-core/src/agents/dsh/index.ts` now supplies an **unregistered** `DshAgent` adapter for the already-owned Main bridge. It cannot spawn a runtime or see a native session id, credential, Home, filesystem or IPC object. The public `DshBridgePort` contract contains only Cindy session, scope and a Main-generated ephemeral capability key; its create/prompt/cancel/close receipts and committed events omit the native id. Main's raw session ref and raw follow envelope are Desktop-private types, and the translator input deliberately has no runtime-id field. Session start requires both `committedFollowProjection` and `promptReceiptLedger` admissions; otherwise it refuses before bridge create. Its externally visible handle is a Cindy-owned SHA-256 opaque id, not a native resume token. It accepts only local text turns, forwards cancellation and close to the bridge, and makes bridge failure a generic reconcile-required terminal state without crossing native error data into maker-core events. It subscribes exclusively through `followCommitted`, and rejects a callback whose contract version, owner tuple, capability key, sequence or per-event projection sequence is invalid.
- `startMacosSupervisedDshBridge` now requires the same Main-owned binding store, prompt receipt ledger and projection journal together; it injects the finite projection coordinator before startup and returns a Main-only `committedFollowProjection` / `promptReceiptLedger` admission token. This closes the contained F2-to-F4 composition gap without registering an agent, adding an IPC surface, or changing product availability. The fixed-Helper-app real E2E was rerun with this exact composition and passed the bounded local prompt/cancel sequence.
- The opt-in fixed-Helper-app integration contains the exact future prompt proof: a random managed scope gets the
  fixed Main-owned profile whose only test provider route is literal `127.0.0.1`; the test injects a deliberately
  fake key, and the loopback fixture accepts only its matching Bearer credential. It uses the real named SQLite
  receipt/projection transactions and asserts a completed first prompt followed by a second locally stalled prompt
  whose public `session/cancel` resolves both the native operation and its durable receipt. The fixture requires
  exactly two `/chat/completions` requests, exposes the first committed follow only after journal commit, checks
  `create → prompt → cancel → close` for runtime/native-message-id or fake-key leakage, and cleans its random scope
  even if provider/profile preparation fails. The Helper now has `com.apple.security.network.client`, while Main
  retains the exact route/profile decision and the supervisor keeps the child environment allowlist. After Main
  canonicalized the root adapter base without its trailing slash, the real build.4 signed-Helper run passed this
  unchanged strict fixture. It is bounded local prompt/follow/cancel evidence, not permission to accept a wider
  route or an availability claim.

## Not proved and unavailable

- The live projection and prompt ledger are still Main-only. They deliberately do not reconstruct missing history, replay a prompt or decide an ambiguous native outcome. The narrow restart guard can only restore a public runtime-listed binding after its receipt ledger is settled; it is not cross-process product recovery. A rejected update retains its sequence for a fresh verified-history reconciler rather than pretending to have consumed it.
- The journal is not a renderer, preload, IPC, device-link, Mobile or user-visible event source. It is not an arbitrary JSON store or a replacement for the runtime's history.
- `DshAgent` is an unregistered, bridge-injected local adapter only. No product agent registration, history replay, cross-process resume, user approval UI, capability upgrade, non-macOS build, remote runner, release, upload, GitHub operation or upstream write was performed.

This is a narrow persistence invariant required before product projection. It does not authorize registering or advertising DSH.
