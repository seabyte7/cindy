# DSH F4 Event Translator Foundation Report

Result: **LOCAL-PARTIAL — maker-core has a bounded, redacting pure translator for a small locally evidenced DSH ACP update surface. Desktop Main applies it to the live owner-scoped follow stream and durably commits its safe result before notifying a product-adapter subscriber through an explicit committed-event port. A Main capability-bound, one-shot permission bridge is locally proven against the unsealed `darwin-arm64` runtime's reject path; the selected signed ACP MVP capability floor still suppresses tools and permissions. None of this is a product event stream or approval surface.**

## Delivered locally

- [`translator.ts`](../../packages/maker-core/src/agents/dsh/translator.ts) accepts only DSH bridge contract version 1, a positive projection sequence and a record-shaped `sessionUpdate`. It has no process, filesystem, database, network, IPC or logging side effect.
- The finite mapping accepts only the locally evidenced `agent_message_chunk`, `agent_thought_chunk`, `tool_call`, `tool_call_update` and `usage_update` shapes. It emits existing `text`, `thinking`, `tool_use`, `tool_result_full`, `tool_result` and non-terminal `status` events. The ACP `used` field is recorded only as context occupancy; the translator does not invent per-turn token totals or cost.
- Unknown updates are ignored. A malformed envelope, native id, text value, tool lifecycle or structured input is rejected and produces no partial product event. Unsupported tool-result content is rejected rather than presenting a partial completion.
- Text and structured input are bounded. The translator rejects control characters in native ids, overlong text, deep or wide JSON, and `__proto__`, `constructor` and `prototype` object keys. Native message/tool ids are converted to scope-bound opaque Cindy event ids; repeated native message ids also include the bridge sequence, so later chunks cannot replace earlier ones.
- Every native text value passes through the repository redactor before it can enter an `AgentEvent`; values under sensitive structured keys such as token, secret, password, authorization, cookie or API key are replaced entirely. The translator does not retain or return the original input object.
- [`DshControlPlane`](../../apps/desktop/src/main/maker-host/dsh-control-plane.ts) keeps a bounded, Main-only association for an active session's successfully translated `tool_call`. An explicit resolver receives only the opaque tool id, title, redacted input and fixed `kind: 'other'`; its native id is consumed before awaiting. Unknown, duplicate, malformed, unavailable, timeout, close, EOF and option-mismatch paths return `{ outcome: { outcome: 'cancelled' } }`.
- With the F3 projection coordinator configured, the control plane queues each owned update. The F0 raw-follow callback remains Main-internal and its envelope does not carry a native runtime session id; an adapter can subscribe only through `followCommitted`, which explicitly contains the Cindy owner tuple, Main-generated ephemeral capability key, sequence and committed `AgentEvent[]` rather than a spread native envelope. Native runtime session ids are omitted from every adapter-facing bridge receipt and event, and Main's raw session / follow types are not exported by Maker Core's bridge port. One-shot tool correlation is also permitted only after the matching translated record has committed. A known unsupported update becomes a finite ignored record; a malformed update or any persistence failure closes the carrier and moves the binding to reconciliation without logging the raw native payload.
- The unregistered `DshAgent` consumes only `followCommitted`. It validates the committed port's owner tuple, positive sequence and per-event projection sequence before queuing an event; receipt or bridge-boundary failure becomes a generic reconcile-required outcome. It remains outside `makerAgents.dsh` and all product surfaces.
- `DshBridgePort.bindPermissionResolver` is capability-bound to the existing Cindy session, scope and Main-generated bridge key. Main retains the native ACP session and `toolCallId`; maker-core receives only an opaque tool id, bounded redacted record input and fixed `kind: 'other'`. The adapter converts a generic interaction `allow` into `allow-once`; any other decision, missing resolver, thrown resolver, close or cleanup becomes `reject-once` or Main's outer `cancelled` response. It never forwards `updatedInput` or `permissionUpdates`.
- A runtime can request permission immediately after its `tool_call` update. With durable projection enabled, Main waits only for that binding's already-queued projection tail and uses the remaining request timeout for the resolver. No raw event is displayed or approved before its finite projection record commits; projection failure, timeout or owner/capability change remains fail-closed.

## Not proved and unavailable

- A real binary follow stream is locally translated, ordered per live owner, journaled with a durable cursor and only then given to the Main bridge subscriber. A separate F3 prompt receipt ledger prevents blind resend after an uncertain native prompt result. History paging/replay, backpressure policy, cross-process recovery and product-level event consumption remain unimplemented; EOF/exit remains fail-closed rather than a recovery proof.
- An unregistered, bridge-injected `DshAgent` and committed subscription owner exist, but no DSH product interaction route, product terminal lifecycle, model/effort, attachment, MCP, profile or extension contract is implemented. The injected resolver is a Main-only one-shot foundation, not a user-available approval flow or a persistent grant.
- Safe projection records reach Main-only SQLite. No event reaches Main IPC, preload, renderer, device-link or Mobile. Therefore this work upgrades no `CapabilityStatus` and does not make text, thought, tool, usage or approval user-available.
- No Linux, Windows, Intel macOS, remote runner, CI, GitHub operation, artifact upload, release, upstream write or remote build was run.

This report is evidence for a narrow local F4 foundation only. It does not authorize DSH product registration or a claim of complete DSH support.
